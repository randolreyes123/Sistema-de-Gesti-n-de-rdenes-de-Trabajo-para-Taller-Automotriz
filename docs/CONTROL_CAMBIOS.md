# Registro breve de cambios y avances

Este registro resume los cambios y avances relevantes realizados durante el desarrollo académico del proyecto.

| N.º | Cambio o avance | Resultado |
|---|---|---|
| 1 | Definición del problema, objetivo, alcance y usuarios | Se estableció una visión clara del sistema y de la necesidad que atiende. |
| 2 | Levantamiento y organización de requisitos | Se documentaron requisitos funcionales, historias de usuario y criterios de aceptación. |
| 3 | Elaboración de modelos UML | Se representaron funciones, estructura, comportamiento y componentes del sistema. |
| 4 | Definición de la arquitectura por capas | Se separaron frontend, servicios/API, lógica de negocio, acceso a datos y base de datos. |
| 5 | Consolidación del seguimiento en GitHub | Se organizaron 10 Issues y un tablero Kanban con prioridad, responsable, fecha estimada y estado. |
| 6 | Actualización de cierre - Semana VIII | Se revisaron los Issues, se documentó el estado actual del tablero y se sincronizaron README y seguimiento con la evidencia real de GitHub. |

## Control de versiones

El repositorio utiliza Git y GitHub como línea base documental. El historial inicial de commits era limitado porque el trabajo de la asignatura se concentró principalmente en análisis, diseño, documentación y seguimiento. Para esta etapa de cierre se actualizó el README, se incorporó documentación técnica específica dentro del directorio `docs/` y se registraron mediante commits las correcciones de seguimiento.

## Trazabilidad del cierre

Los Issues mantienen la información histórica de la Semana VI y ahora incluyen un bloque de actualización de la Semana VIII con su estado actual. Los elementos finalizados permanecen cerrados como completados, mientras que los pendientes permanecen abiertos para conservar la continuidad del proyecto.

## Mejora recomendada para la siguiente etapa

Cada futura modificación de código debe relacionarse con un Issue y quedar registrada mediante commits descriptivos y, cuando corresponda, Pull Requests. Esto permitirá mantener trazabilidad entre requisito, implementación y prueba.
